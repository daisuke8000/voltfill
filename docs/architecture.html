VOLTFILL · Architecture & C4

PDFの原文から、フォームの値を。

VOLTFILLは、PDFのテキスト層から、指定されたフォーム項目に当てはまる原文の値を、ページと座標の根拠（Evidence）付きで返します。文字を生成・読み取りせず、モデル（Jev）は「どの原文か」「どこにあるか」を選ぶためだけに使います。UIは別のWebアプリが担います。

現在、旧来の抽出（Text／Vision／Hybrid）からフォーム入力向けの構成へ移行中です。図では実装状況を区別しています。

01

処理の流れ

入力はPDFとフォーム項目の一覧（id・ラベル・型・別名）。出力は項目ごとの値・根拠・状態です。原則は「誤って埋めるより空欄」です。

L1 読むvf-source

テキスト片と座標、ページごとのテキスト有無と品質を取得します。フォント非埋め込みなどで文字化けした片は suspect として除外します。

実装済み
L2 構造化vf-source

片を行にまとめ、ラベルと値の候補を作ります（1つの片の中の「ラベル：値」、同じ行の右とその続きの行、真下の1行）。各候補に結び付き方を付けます（区切り記号：「ラベル：値」か、「ラベル：」の片と4em以内の右の片／位置だけ：区切り記号のない右隣・4emより離れた右隣・真下・列）。値は既存の片のバイト範囲で、片の一部の座標は推定値として明示します。境目が決まらない片（「ラベル：」が複数）は分けず、ラベルの列（上下の行が右に値を持つ列）の真下は値にしません。「ラベル：値」の値も続きの行を拾い、続きの行に別の列の片があっても値を途中で切りません。見出しや1列の一覧の下に2行以上のデータ行がある場合は、値ではなく列として示します（行の間隔は見出しから1行目までで測り、空欄のセルの行も数えます）。候補は1文書50,000件、値は5行までで、超えた値は切り詰めずに外します。片の原文は分類と寸法計算の2回だけ読み、探索は1行あたり16片までで、作業量と期限で打ち切ります。複数行の明細値・AcroFormは未対応です。

実装中
L3 当てるvf-core

フォームのラベル・別名・型で候補を採点し、厳格な確定方針で埋めます。ラベルが正規化のうえで完全に一致し（先頭の「ご」「御」「お」は無視）、区切り記号で値と結び付き、値が1行で1つだけで、型の書式に合う候補が最上位にそろって同じ値を許すときだけ確定します。部分一致のラベル・片方にだけ補足があるラベル・位置だけの結び付き（右隣・真下・表や一覧）・複数行の値・すぐ右に区切り記号のない片があり途中で切れている可能性のある値・値が2つ以上ある値は、理由（hold）付きの候補にとどめ、誤った値より空欄を優先します。レイアウト解析と照合の作業量と期限に上限があり（CLIの既定は30秒）、超えると部分結果ではなくエラーを返します。決めきれない項目だけ、--remote 指定時にJevに候補から選ばせます（ラベルと候補の原文だけを送り、ページ画像は送りません。確定できない理由がラベルか位置の結び付きだけの候補を選択肢にし、値が2つ以上・複数行・途中で切れている可能性がある・型に合わない候補は、最初の理由がラベルや結び付きでも、選んでも1つの値にならないため選択肢にしません）。期限はJevへの送信前のオフラインの処理だけに適用します。どちらも voltfill fill で利用できます。Jevによる補助は模擬応答で試験済みで、実APIでは未測定です。

実装中
L4 返すvf-core

原文・正規化値（値全体が1つの日付・金額・数値に合う場合だけ。和暦と一致する括弧付きの曜日、通貨記号または「円」・税込/税抜の注記・負の記号（△ ▲ − -）の付いた金額に対応し、括弧で囲んだ金額・先頭に余分な0がある数・期間・範囲・「以降」「約」「以上」付きや、単位が千円・万円のラベルの値、単位の注記（「単位は千円」「千円単位」を含む）がある文書の金額・数値は、注記と別のページでも変換しません）・根拠（ページ・座標・精度）・状態（filled / ambiguous / not_found / no_text / invalid）を返します。Evidenceと受信本文の保存は既存の仕組みを引き継ぎます。

実装中
02 · C4 Level 1

System context

VOLTFILLはUIを持たない処理エンジンです。WebアプリのバックエンドやCLIの利用者から呼ばれ、必要なときだけJev APIに問い合わせます。

03 · C4 Level 2

Containers

CLIとHTTPサーバーは同じ処理を呼ぶ薄い入口です。複数の要求でJevの送信量・費用の上限を共有する場合はHTTPサーバーを常駐させます。

04 · C4 Level 3

Components（crate）

基盤crateは抽出スキーマやEvidenceに依存せず、vf-core・vf-legacyに依存しません。vf-coreはvf-legacyに依存しないため、旧方式はcrateごと削除できます。実行ファイルは vf-cli が作る voltfill だけです。

依存の約束

  • vf-source・vf-render は抽出スキーマ・Evidenceを必要としない
  • vf-client は PDF crate と vf-core・vf-legacy に依存しない
  • 基盤crateは vf-core・vf-legacy に依存しない
  • vf-core は vf-legacy に依存しない
  • vf-core は Jev への送信に vf-client だけを使う（assist）

外部crate

PDF解析は pdf-inspector と lopdf、HTTPは reqwest（rustls）、サーバーは axum / tokio。描画の hayro・PDFium は既定オフです。

移行の方針

新しいL2〜L4（vf-core）は旧方式（vf-legacy）と並べて作り、同じPDFでの比較（誤入力率→空欄率→トークン→時間の順）で方式を決めてから vf-legacy を削除します。

05

Jevへの問い合わせ

Jevは文字列を返さず、選択（choice）・有無（noul）・位置（box）だけを答えます。値は必ずPDFの原文から取ります。

候補から選ぶ 実装済み

原文の候補を choice の選択肢として渡し、どれかを選ばせます（該当なしも選択肢に含む）。fill --remote は曖昧な項目だけを、項目のラベル・型・別名と候補のページ・原文のラベルと値として送ります（前後の行・画像は送りません）。確定できない理由（holds）がラベルか位置の結び付きだけの候補を選択肢にし、値が2つ以上・複数行・途中で切れている可能性の理由を1つでも持つ候補と、型に合わない候補は選択肢にしません。選ばれた候補が確率の単独最大で確率の合計が1のときだけ、その候補の原文とEvidenceで埋めます。模擬応答で試験済みで、実APIでは未測定です。

位置を指す 実装済み

ページ画像を渡して box で値の位置を答えさせ、座標をPDFに戻して範囲内の原文片を値にします（Vision）。片の一部だけを囲む場合はL2の分割で対応します。

送らないもの

認証情報・HTTPヘッダー・本文はログに出しません。送信には明示的な --remote が必要で、送信回数・トークン・費用・期限の上限を全試行に適用します。

{ "questions": { "q0": { "type": "choice",
    "instructions": "フォーム項目「金額」（金額）の値を、PDFの原文から作った候補（ページ ラベル: 値）から1つ選んでください。別名: 小計、合計。…",
    "criteria": { "c0": "p1 小計: ¥11,000", "c1": "p1 合計: ¥12,100", "none": "該当なし（…）" } } } }
→ { "answers": { "q0": { "type": "choice", "choice": "c1",
    "probabilities": { "c0": 0.1, "c1": 0.85, "none": 0.05 }, "confidence": 0.9 } } }
06

守る約束

原文と根拠

値はPDFの原文から取り、文字を生成・OCRしません。Evidenceと全試行の受信本文（再試行・エラー・不完全な本文を含む）を保存します。推定した座標は推定と明示します。

評価専用

結果は評価専用で、confidenceは校正済みの正答確率ではありません。モックの結果を実際の精度・性能として扱いません。

依存とネイティブ

ネイティブ描画は任意で、利用者が指定したライブラリパスだけを使い、自動取得しません。RUSTSEC-2026-0192（ttf-parserの保守警告）は抑止せず追跡します。
