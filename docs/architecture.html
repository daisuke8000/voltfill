送信前

送信頻度、トークン数、並列数、コンテキストの推定上限、期限を設定できる。推定量に応じて質問を分割し、1件でも収まらなければ原文を切り捨てず送信前に非対応とする。再試行ごとにそのリクエストの推定量を予約する。再試行にも同じ制限を適用する。実行中の同期的なPDF解析や描画は、期限を過ぎても強制中断できない。

再試行

待ち時間は指数バックオフとjitterで調整し、上限を設ける。Retry-Afterの指定時間より早くは再送しない。試行回数は初回を含め1〜3回。

並列とバッチ

独立した質問をバッチにまとめ、設定した並列数と送信上限の範囲で実行する。

Mermaidの詳細モデルを表示
sequenceDiagram
    participant Adapter as CLI / HTTP / library caller
    participant Engine
    participant PDF as Snapshot / candidates / renderer
    participant Eval as Evaluator
    participant Control as Execution controller
    participant API as Jev
    Adapter->>Engine: PDF + validated schema + options
    Engine->>PDF: Build snapshot; prepare scoped source/images
    loop Dependency waves
        Engine->>Eval: Compatible independent question batches
        loop Each attempt within configured bounds
            Eval->>Control: Reserve request/tokens/cost; await admission
            Control-->>Eval: Permit or bounded failure
            Eval->>API: HTTPS request
            API-->>Eval: HTTP status + original body
            Eval->>Eval: Retain original body before validation
            opt Retryable and budget/deadline allows
                Eval->>Control: Wait exponential backoff + jitter / Retry-After
            end
        end
        Eval-->>Engine: Answers/errors + usage + original responses
        Engine->>Engine: Resolve source, validate, check provenance
    end
    Engine-->>Adapter: Partial report or error with received responses

起動と設定

runとserveは共通コアを使い、起動時の設定をPDF・描画の資源制限とJevの送信制御に適用します。PDFium・Hayroは任意のfeatureで、PDFiumには明示したライブラリパスが必要です。設定項目と優先順位は設定ガイドの起動設定を参照してください。

HTTP受付

アップロードの上限はPDF 16 MiB、schema 1 MiB、options 64 KiBで、アップロードの期限は30秒。別の処理を実行中は429を返して受け付けない。

公開・隔離の設定

既定の待ち受け先はループバック。外部アドレスでの待ち受けと、Originヘッダー付きの抽出リクエストにはBearer認証が必須。Jevに接続するサーバーで画像を使った抽出を受け付けるには、起動時に--allow-imagesを指定する。TLSの終端処理や、不正なPDFに備えたOS・ワーカーでの隔離は運用側で用意する。

原文との対応

原文の文字列と正規化後の値は分けて保持する。同じ文字列でも、出現位置が違えば別の候補として扱う。一部のページだけを調べた結果から、文書全体に値がないとは断定しない。

レスポンスの保持

受信した本文がUTF-8なら元の文字列、それ以外ならバイト列として返す。未知のキーを含む応答、検証に通らなかった応答、再試行中の応答も保持する。受信失敗や容量上限は明示し、本文が不完全な場合や受信できなかった試行ではbody_completeをfalseにする。

抽出できる条件

抽出には、読み取れる文字情報と座標が必要。文字コードと実際に表示される文字が一致しないPDFには対応できない場合がある。

VOLTFILL · Best-effort PDF extraction · PDFへの書き込み、OCR、自動フォーム送信は現在の実装範囲外です。
入力サイズ・ページ数の上限では、依存ライブラリ内部のストリーム展開や予測復元の割り当てをすべて制限できません。信頼できないPDFでメモリを使い切る可能性があり、VOLTFILL自体はプロセス隔離を提供しません。送信制御は同じ実行コントローラーを使う処理に適用されます。
