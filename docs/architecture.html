VOLTFILL · Architecture & C4

PDFの原文から、フォームの値を。

VOLTFILLは、PDFのテキスト層から、フォーム項目に当てはまる原文の値をページと座標の根拠（Evidence）付きで返す、UIを持たないエンジンです。原則は「誤って埋めるより空欄」。Jevは「どの候補か」「どこにあるか」を答えるだけで、文字は生成しません。

01

処理の流れ

入力はPDFとフォーム項目（id・ラベル・型・別名、表は列）。出力は項目ごとの状態・原文・正規化値・根拠です。

L1 読むvf-source

テキスト片・座標・品質と、AcroFormのフィールド値を読みます。文字化けした片、斜め・縦書きのページは値に使いません。

実装済み
L2 構造化vf-source

片を行にまとめ、ラベルと値の候補と表を作ります。回転した片はその向きで同じ規則を使います。

実装済み
L3 当てるvf-core

ラベル・型・別名で候補を採点し、厳格な確定方針で埋めます。確定できない候補には理由（hold）を付けて返します。

実装済み
L4 補うvf-core · 任意

--remote で残った候補をJevに選ばせ、--images でページ画像から値の位置を指させます。値は常にその位置の原文です。

実装済み
L5 返すvf-core

項目ごとの status・原文・正規化値（日付・金額・数値）・Evidenceと、Jevの全受信本文を返します。

実装済み
02 · C4 Level 1

System context

VOLTFILLはWebアプリのバックエンドやCLIから呼ばれ、--remote のときだけJev APIに問い合わせます。

03 · C4 Level 2

Containers

実行ファイルは voltfill だけです。CLIとHTTPサーバーは同じライブラリを呼ぶ薄い入口です。

04 · C4 Level 3

Components（crate）

依存は上から下への一方向です。基盤crate（vf-source・vf-render・vf-client）は vf-core 以上を知りません。

依存の約束

  • vf-client は PDF の crate と vf-core に依存しない
  • vf-source・vf-render はフォームもEvidenceも知らない
  • vf-core は Jev への送信に vf-client だけ、描画に vf-render だけを使う

外部crate

PDF解析は pdf-inspector と lopdf、HTTPは reqwest（rustls）、サーバーは axum / tokio。描画の hayro・PDFium は既定オフ。

05 · C4 Level 3

vf-core の内部

オフラインの照合で決まらない項目だけが、任意の補助（Jev）に進みます。

06

Jevへの問い合わせ

Jevは文字列を返さず、選択（choice）・有無（noul）・位置（box）だけを答えます。値は必ずPDFの原文から取ります。

候補から選ぶ --remote

未確定の項目のラベルと、候補のページ・ラベル・値を choice の選択肢として送ります。確率が単独最大の候補だけを採用します。

位置を指す --images

ページ画像を送り、noul で有無、box で値の位置を答えさせます。枠内の原文片が1つに決まり、ラベルと型の検査を通るときだけ埋めます。スキャンのページは位置だけを返します。

上限と記録

送信回数・トークン・費用・期限の上限を全試行に適用し、再試行・エラーを含む全受信本文を結果に残します。

{ "questions": { "q0": { "type": "choice",
    "instructions": "フォーム項目「金額」の値を、PDFの原文から作った候補から1つ選んでください。…",
    "criteria": { "c0": "p1 小計: ¥11,000", "c1": "p1 合計: ¥12,100", "none": "該当なし" } } } }
→ { "answers": { "q0": { "type": "choice", "choice": "c1",
    "probabilities": { "c0": 0.1, "c1": 0.85, "none": 0.05 } } } }
07

結果の状態

status意味
filled値が1つに決まった（method: label_match・table_match・acroform・jev_choice・jev_box）
ambiguous候補が決まらない。理由（hold）付きの候補を返す
not_found候補がない
no_text使えるテキスト層がない（スキャンなど）
invalid値が型の書式に合わない
08

守る約束

原文と根拠

値はPDFの原文から取り、生成・OCRしません。推定した座標は推定と明示します。

送信と記録

Jevへの送信は明示的な --remote が必要です。本文・認証情報・HTTPヘッダーはログに出しません。

評価専用

confidenceは校正済みの確率ではなく、模擬応答の結果を実際の精度として扱いません。

依存とネイティブ

PDFiumは利用者が指定したパスだけを使い、自動取得しません。RUSTSEC-2026-0192 は抑止せず追跡します。
