# 実APIベンチマーク

[English](benchmarks.en.md) · 日本語

2026-10-18に、再作成した2ページ・20項目の合成PDFでJev実APIを測定しました。CLIとHTTPを分け、それぞれでText・Vision・Hybrid、PDFium・Hayroを比較しています。**10条件を各1回、同じ入力で測定しました。**

今回のPDFは旧測定のPDFとハッシュ・原文座標が異なります。旧測定との直接の性能優劣比較はできません。入力PDFと専用データは、このリポジトリには含めていません。

## 測定結果の要点

- **返却値と全文一致**： 全10条件で20項目ずつ、合計200値と対応するEvidenceを保持し、errorは0でした。全文一致は164/200、一部一致は36/200、余分な原文の混入と値なしは0でした。ambiguousの警告は4項目に残っています。
- **条件別の全文一致**： CLIの全文一致はText 6、Vision PDFium 18／Hayro 19、Hybrid PDFium 20／Hayro 20。HTTPは同じ順に6／18／19／20／18でした。
- **Box confidence**：Hybridの平均が高い結果。 80組中、Hybridが高いのは53組、低いのは23組、同じなのは4組。平均はVision 0.76075、Hybrid 0.78725です。回答に付いたスコアであり、正答率の改善を示しません。
- **時間と入力使用量**：時間・入力トークン数ともVisionが少ない結果。 同じ経路・描画のHybridはVisionの2.6894〜3.8786倍の全体時間、5.0876〜5.3793倍の入力トークン数でした。再試行分を含みます。
- **Textの出力範囲**：単一候補スキーマ。 各経路とも2 POST、全文一致6項目・一部一致14項目でした。新しいText複数取得は今回測定していません。

この1入力・各1回の結果から方式の一般的な精度や性能を順位づけません。全文一致、欠けた原文、警告、時間、使用量を分けて確認してください。

## 比較の前提

| 項目 | 条件 |
|---|---|
| 入力 | 全条件で同じ再作成PDF1件、2ページ、20項目 |
| モデル | `jev-1.14.0` |
| 描画 | PDFium / Hayro、`1.5 pixels/point`、自動フォールバックなし |
| 並列数 | 1回の抽出内で最大2 POST。条件ごとの試験は1つずつ実行 |
| 送信頻度 | 最大2 POST/秒 |
| バッチ | 最大10質問。ページ・入力種別・依存する質問ごとに分割 |
| 質問数 | Text 20 / Vision 40 / Hybrid 60。従来の3スキーマを変更せず使用 |
| 再試行 | 初回を含め最大3試行。POST上限はText 6 / Vision 12 / Hybrid 18 |
| 入力予約量 | 最大100,000 tokens/秒、1試行64,000 tokens |
| 文脈の制限 | 1リクエスト64,000 / 1質問32,000 tokens。画像見積もりは1出現16,000 tokens |
| 費用予約上限 | 各抽出50,000,000 nano USD。見積単価に基づく予約で、提供元の実請求額の上限保証ではない |
| タイムアウト | 全体180秒、1回のPOSTは10秒 |
| confidence profile | 未指定。confidenceで値を落とさない |
| 出力契約 | Textは単一候補。Vision・Hybridは複数の原文断片を配列で返す |
| 時間の範囲 | VOLTFILL内部の処理時間。CLI起動とHTTPアップロード・応答の通信往復は含まない |
| 測定回数 | 各条件1回。反復測定の平均・p95・統計的な有意差は未評価 |

全文一致は全原文断片が順序・空白も含めて完全に一致した状態です。一部一致は原文断片の一部だけを返した状態です。警告数は`status`が`extracted`以外の項目数で、全文一致とは別に数えます。以下のconfidenceは再試行を含む受信順で各項目の最終Box回答を選び、20項目を算術平均した値です。全試行の平均や反復試験の平均ではありません。

TextのChoice confidenceは質問型が異なるため併記しません。usageは再試行分を含みます。

## 項目別の欠落と警告

| 条件 | 返却値に含まれなかった原文 |
|---|---|
| Vision／PDFium（CLI・HTTP） | 項目14の先頭断片、項目20の末尾断片 |
| Vision／Hayro（CLI・HTTP） | 項目20の末尾断片 |
| Hybrid／Hayro（HTTP） | 項目14の先頭断片、項目20の末尾断片 |

これらは返却範囲の欠落であり、描画そのものの欠落が原因だとは確定していません。上記以外のVision・Hybridの項目は全文一致でした。Textでは単一候補という出力契約により、複数断片の項目が一部一致です。

| 警告のある条件・項目 | status / reason | 保持された内容 |
|---|---|---|
| Text（CLI・HTTP）項目10 | `ambiguous` / `probability_sum_not_one` | 選択値とEvidence。CLI終了コード3でも値は保持 |
| Hybrid／PDFium（HTTP）項目17 | `ambiguous` / `probability_sum_not_one` | 全文一致する配列とEvidence |
| Hybrid／Hayro（HTTP）項目14 | `ambiguous` / `hybrid_source_disagreement` | Boxから解決した配列とEvidence。全文では一部一致 |

確率合計や文字・画像の不一致を理由に、受信済みの値やEvidenceを削除していません。原レスポンスもすべて保持しています。警告付きの値を無条件の成功として扱うことはできません。

## 描画エンジンと実行経路

全文一致数は経路・描画で異なります。CLIのHybridは両描画で20/20、HTTPのHybridはPDFium 20/20・Hayro 18/20でした。これは各1回の結果であり、描画品質の優劣を採点したものではありません。値が一致しても、画像・Box・Evidence座標が同一とは限りません。

入力とモデルは全条件で共通です。スキーマと設定上限は方式ごとに定め、同じ方式のCLI・HTTPと描画エンジン間でそろえました。CLIとHTTPは共通の抽出・送信処理を使いますが、入口はファイル読み取りとアップロード受信で異なります。送信本文全体のバイト一致は未検証です。CLIとHTTPの時間差から、サーバー自体の速度や方式の一般的な性能を推定できません。
