Architecture

Source inspection, rendering and model evaluation.

100%

Reusable foundation crates

Arrows show crate dependencies. Foundations require no schema or Evidence. Core owns extraction output, aggregate timings/usage and field/page associations; PDF inspection has independent timings. Recording preserves every received attempt body before validation; logs contain no bodies, credentials or headers. Existing core API paths and default-off renderer features remain supported. Image-only PDFs can be inspected/rendered without OCR; extraction still requires source Evidence.

Execution sequence

Question dependencies, request control and original responses.

100%

Before sending

Configure request rate, token rate, concurrency, context estimates and deadlines. Split questions to fit per-request and per-question estimates; reject an indivisible oversized question without truncating its source. Reserve the request estimate for every retry. The same limits apply to retries. Deadlines cannot forcibly interrupt a synchronous PDF parser or renderer call.

Retries

Uses capped exponential backoff with jitter and honors Retry-After. One to three attempts, including the initial request.

Concurrency and batches

Batches independent questions and executes them within configured concurrency and rate limits.

Launch and configuration

Both run and serve use the shared core, applying startup settings to PDF/render resource limits and Jev execution control. PDFium and Hayro are optional features; PDFium requires an explicit library path. See Launch configuration guide for settings and precedence.

HTTP admission

Uploads allow 16 MiB PDF, 1 MiB schema and 64 KiB options, with a 30-second upload deadline. Busy requests receive 429.

Deployment boundary

Binds to loopback by default. Non-loopback binding and extraction requests with an Origin header require Bearer authentication. A remote server must be started with --allow-images to accept image-based extraction. Deployments provide TLS ingress and parser isolation.

Source correspondence

Preserves original text separately from normalized values. Positions distinguish identical strings. Partial scope cannot establish document-wide absence.

Response retention

Returns received UTF-8 bodies as original strings and other bodies as bytes, including retries and validation failures. Receive failures and limits are explicit; body_complete is false for incomplete bodies or attempts without a received body.

Requirements

Requires usable text and coordinates. PDFs whose character mappings differ from visible glyphs may not be supported.

VOLTFILL · Best-effort PDF extraction · PDF editing, OCR and form submission are not supported.
Input/page limits do not bound all upstream stream decompression or predictor allocations. Untrusted PDFs can exhaust process memory; VOLTFILL does not provide process isolation. Rate control applies to operations using the same execution controller.
