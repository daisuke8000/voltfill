# VOLTFILL

PDFのテキスト層（入力欄つきPDFではAcroFormのフィールド値も）から、指定された項目に対応する原文の値を根拠（Evidence）付きで返すRust製CLI／HTTPサーバーです。PDFは変更しません。構成と実装状況は[アーキテクチャ・C4](https://daisuke8000.github.io/voltfill/)を参照してください。

> 機能の範囲を絞り込み中です。Vision／Hybrid方式とスキーマ形式は今後変更されます。

## インストール

Rust 1.99.1で、リポジトリのルートから実行します。

```sh
cargo install --path crates/vf-cli --locked
```

## 使い方

Jevに送信せず、PDFのテキストと座標を確認します。

```sh
voltfill inspect input.pdf
```

<a id="fill"></a>

### フォーム入力（fill）

フォーム項目の一覧（[例](examples/forms/invoice.json)）を渡すと、PDFの原文から各項目の値を探して返します。`--remote` を付けない限りJevには送信しません。

```sh
voltfill fill input.pdf examples/forms/invoice.json -o result.json
```

項目は `id`・`label`・`type`（`text` / `date` / `amount` / `number`、既定 `text`）・`hints`（ラベルの別名）です。明細のような表は `type: "table"` の項目で行ごとに読みます（[表の項目](#fill-table)）。

オフラインの照合は**厳格な確定方針**です。値を入れる（`filled`）のは、次の4条件をすべて満たす候補だけです。それ以外の候補は値を入れず、確定できない理由（`hold`）を付けて `candidates` で返します。誤って埋めるより空欄を優先し、オフラインで埋まる項目が減ることは許容します。候補は、`--remote` を付けるとJevに候補から選ばせて決められます（[下記](#fill-remote)）。ページ画像で位置を答えさせる補助は未実装です。

1. **ラベルが一致する**: 文書のラベルが、フォームの `label` か `hints` のどれかと正規化（全角半角などのNFKC・空白の除去・末尾の `：` `:` の除去・英字の小文字化）のうえで等しい。先頭の `ご`・`御`・`お` は1つだけ無視します（`ご住所` = `住所`）。括弧内は補足として扱い、補足まで等しいことが必要です（全体が括弧のラベル `【住所】` は中身 `住所` として扱います）。片方がもう片方を含むだけのラベル（文書の `再発行日` とフォームの `発行日`）と、片方にだけ補足があるラベル（文書の `消費税（10%）` とフォームの `消費税`）は候補止まりです。補足が異なるラベル（`金額（税込）` と `金額（税抜）`）は候補にもしません。補足まで同じラベル（`消費税（10%）`）を `label` か `hints` に書けば一致します。
2. **区切り記号で結び付く**: 1つの片の中の `ラベル：値`・`ラベル: 値`、または `ラベル：` で終わる片と、同じ行のすぐ右の片で、間が4em以内のもの（emは2つの片の高さの小さいほう。右の片が大きくても、小さいラベルから届く距離は広がりません。約0.5em未満の間のランは抽出で1つの片になるため、別の片の値はおよそ0.5〜4em右にあります）。区切り記号のない右隣・`ラベル：` から4emより離れた右隣（記入前の `氏名：` と右端の会社名など）・ラベルの真下・表や一覧の列は、位置だけの結び付きなので候補止まりです。1つの片の中で空白だけで分かれた「ラベル 値」（`発行日 2026年11月8日`）も候補止まりです（下記）。
3. **値が1つ**: 値が1行で、値に含めたどの行でも、その片の同じ行のすぐ右に、区切り記号のない片が（距離によらず）ないこと（あれば、値が複数のランに分かれて途中で切れているか、区切り記号のない別の値が続く可能性があります。すぐ右が `ラベル：` や `ラベル：値` の片なら次の項目なので対象外です）。文字列の値は、さらに値を2つ以上含まないこと（下記）。
4. **型に合う**: 日付・金額・数値は、値全体が下の表の書式に一致すること（一致しなければ `invalid`）。

最上位の得点の候補（完全一致があれば完全一致、なければ最も近い部分一致）だけで決めます。そのすべてが4条件を満たし、同じ値を許すときだけ埋めます。最上位に `hold` 付きの候補が1つでもあれば `ambiguous` で、得点の低い候補で埋めることはしません（例: 同じラベルが「ラベル：値」と区切り記号のない形の両方にあれば埋めません）。候補の `holds` は満たさなかった条件をすべて上の順で示し、`hold` はその最初の条件です。

| `hold` | 理由 |
|---|---|
| `partial_label` | 文書のラベルがフォームのラベルを含む、または含まれるだけ（条件1） |
| `one_sided_qualifier` | 片方のラベルにだけ括弧内の補足がある（条件1） |
| `geometric_only` | 区切り記号がないか `ラベル：` から4emより離れていて、位置だけで値と結び付く（右隣・真下・表や一覧の列、条件2） |
| `no_delimiter` | 1つの片の中で、ラベルと値が空白だけで分かれている（`発行日 2026年11月8日`、条件2） |
| `multi_line` | 値が2行以上（条件3） |
| `split_value` | 値の片の同じ行のすぐ右に区切り記号のない片がある（距離によらない。`住所：` `〒100-0001` `東京都千代田区…`・`氏名：山田` `太郎`、条件3） |
| `several_values` | 文字列の値に値が2つ以上ある（条件3） |

文字列の値は、次のどれかに当たると `several_values` です。

- 電話番号が2つある（`03-1234-5678 FAX 03-1234-5679`・`03-1234-5678、03-1234-5679`・`03-1234-5678／03-1234-5679`）。電話番号として扱うのは、ハイフンでつないだ3つ以上の数字のまとまりで合計9〜13桁のもの、`0` で始まる10〜11桁の数字（`0312345678`）、`0` で始まる市外局番を括弧で囲んだ合計10〜11桁のもの（`(03)1234-5678`・`03(1234)5678`）です。ハイフンでつないだ3つ以上の数字のまとまりが電話番号より長い（13桁か25文字を超える）もの（`03-1234-5678-03-1234-5679`）も、電話番号が続けて書かれているとみなし同じ扱いです。
- 日付または金額が2つあり、その間が範囲の記号（`〜`・`~`・`-`・`−` など）だけではない（`2026年11月8日、2026年12月1日`・`1,000円 と 500円`）。`2026年11月8日〜2026年12月8日`・`¥1,000〜¥2,000` のような範囲は1つの値です。
- 電話番号・日付・金額の直前（空白・通貨記号・符号は除く）に語があり、その語の前にも文字がある。区切り記号のない2つ目のラベルと値とみなします（`山田 太郎 生年月日 1990年1月1日`）。値の先頭の語（`TEL 03-1234-5678`）は対象外です。
- 値を空白・`/`・`／`・`・`・`、`・`,` で区切った語のうち、先頭の語を除くどれかが、フォームのどれかの項目の `label` か `hints` と正規化のうえで等しい。区切り記号のない2つ目の項目とみなします（フォームに `所属` がある場合の `山田 太郎 所属 経理部`・`山田 太郎/所属 経理部`）。語の途中は区切らないため、`山田太郎・所属経理部` は対象外です。
- 電話番号・日付・金額（金額は後ろの `円` も含む）の後ろに、空白と語が続き、その語の後に空白と別の文字が続く（`03-1234-5678 担当 山田`）、数字がすぐ続く（`03-1234-5678 内線123`。`Ext.123`・`内線#123` のように `.`・`#`・`:` を挟む場合も同じ）、または何も続かず語が3文字以上（`03-1234-5678 担当山田`）。内線（`03-1234-5678 内線 123`・`内線123`）も別の項目の値と区別できないため同じ扱いです。後ろが2文字までの語だけ（`03-1234-5678 代表`・`2026年11月8日 必着`）や括弧（`(代表)`・`(税込)`）なら1つの値です。3文字以上の語（`1,000円 税込み`）は、ラベルと値が空白なしで続くものと区別できないため `several_values` です。

複数行の値は、ラベルの右の値ではその値の左端にそろう片、「ラベル：値」の値では片の左端から値の推定開始位置の1.5行高さ右までに始まる片が、次の行にあれば続きです。続きの行にほかの片（2段組のもう一方の列など）があっても、その位置に始まる最初の片を続きとみなし、値を途中で切りません。ただし、ラベルの右の値では、その片より左でラベルと同じ列（左端か右端がそろうか、横に重なる）に片がある行は次の行の項目とみなし、続きにしません（`小計` / `合計` の行）。続きは「ラベル：値」・「ラベル：」の行の手前で終わり、値の2行目以降がフォームのラベルと同じならその手前で終わります（終わった結果が1行なら1行の値です）。値の1行目がフォームのラベルと同じなら、隣のラベルとみなして候補にしません。

区切り記号のない「ラベル 値」は、区切り記号のない1つの片（抽出時に空白付きで結合された2つのランを含む）が、フォームの `label` か `hints` と条件1の意味で完全に一致する語（先頭の `ご`・`御`・`お` は無視）で始まり、空白（半角スペース・タブ・全角スペース）が続く場合だけ、その後ろを値とする候補（`hold`: `no_delimiter`）にします。ノーブレークスペースなどほかの空白では、ラベルも値の語も分けません。分割を試すのは、片の先頭から96バイト以内で始まる最初の4か所の空白までで、96バイトを超える空白が続くとそこで探すのを止めます。値は原文のバイト範囲で、座標は推定（`estimated`）です。ラベルの語は文の書き出しにも現れるため、次の場合は候補にもしません。

- 値の中に、フォームの `label` か `hints` と条件1の意味で完全に一致する語がある（`姓 山田 名 太郎` の `名`・`氏名 山田太郎　所属 経理部` の `所属`・`First Name John Last Name Smith` の `Last Name`・表の見出し `品名 数量 単価 金額` の `金額`）。値の各語から始まる連続した1〜4語（96バイトまで）を、間の空白ごとラベルと比べます（`Last Name`・`合計 金額` のような空白を含むラベルも一致します）。フォームにないラベル（フォームに `所属` がない場合の `所属`）は見分けられず、値の一部になります。
- 値が2行以上、値が2つ以上（`several_values` に当たる。例: `TEL 03-1234-5678 FAX 03-1234-5679`）、値の片の同じ行のすぐ右に区切り記号のない片がある（`split_value` に当たる）、または型の書式に合わない（`発行日 2026年11月8日以前の…`・`合計 金額は…`）。`no_delimiter` 以外の理由が付く候補は返さないため、この候補の `hold` と `holds` は常に `no_delimiter` だけです。
- 続きの行は「ラベル：値」の値と同じ範囲から取りますが、フォームのラベルと空白で始まる行の手前で終わります。フォームにないラベルの行（`振込先 …`）が続くと、前の値は2行とみなして候補にしません。続きの行の中にあるラベルは調べませんが、2行以上の値は候補にしないため返りません。

この候補はほかのどの候補よりも下位で、最上位の組に加わりません。ほかの候補がある項目の結果（`filled`・`ambiguous`・`invalid`）は変えず、候補の一覧の後ろに並ぶだけです（`発行日：2026年11月8日` と `発行日 2026年12月1日` があれば前者で埋めます）。この候補しかない項目は `ambiguous` で、`--remote` を付けるとJevがこの候補から選べます。ラベルの語で始まる文字列項目の文（`氏名 は楷書で…`）も候補になりますが、オフラインでは埋めません。

結果は項目ごとに `status` を持ちます。

| status | 意味 |
|---|---|
| `filled` | 値が1つに決まった。`raw`（原文）・`value`（日付はISO形式、金額・数値は数値）・`evidence` を返す |
| `ambiguous` | 最上位の候補の値が分かれた、または最上位の候補に `hold` 付きのものがある。`candidates` を返す |
| `not_found` | ラベルに対応する値の候補がない |
| `no_text` | 使えるテキスト層がない（スキャンPDF・文字化け） |
| `invalid` | 最上位の候補の値がどれも型の書式に合わない。`raw` と `candidates` を返す |
| `limit_exceeded` | 処理量の上限を超えたため評価していない（ライブラリの `fill` のみ。CLIはエラーで終了） |

`evidence` はページ・原文片のIDとバイト範囲・座標（PDFポイント、左上原点）です。1つの片を「ラベル：値」で分けた場合の座標は文字幅からの推定で、`precision: "estimated"` と示します。`candidates` は得点順（空白だけで分けた候補はほかの候補の後）に最大5件（[AcroForm](#fill-acroform)の候補はその前に加わります）で、それぞれ文書のラベル・原文・正規化値・得点・配置（`inline` / `right` / `below` / `column`、AcroFormの値は `widget`）・`hold`・`holds`・`evidence` を持ちます。

| 型 | 受け付ける書式（全角は半角に正規化） |
|---|---|
| `date` | 1つの日付（`2026年11月8日`・`2026/11/08`・`2026-11-8`・`2026.11.08`・和暦）。後ろに付けてよいのは、その日付と一致する括弧付きの曜日（`(日)`・`（日曜日）`・`(Sun)`）だけ |
| `amount` | `[符号] [¥ ￥ $ €] [符号] 数 [円] [注記]`。符号は `-`・`−`・`△`・`▲` のどれか1つで、負の金額になる。全体を囲む括弧（`（1,000円）`）は負の記号とみなさず `invalid`。通貨記号は前置か `円` のどちらか一方。小数は2桁まで。注記は `（税込）`・`（税抜）`・`(税込)`・`(税抜)`・`税込`・`税抜` のどれか1つ |
| `number` | `[- − +] 数 [単位]`。単位は `個`・`点`・`件`・`名`・`人`・`枚`・`本`・`台`・`回`・`kg`・`g`・`km`・`m`・`cm`・`mm`・`m2`（`㎡`・`m²`）のどれか1つ |

数は内部に空白を含まない数字で、3桁区切りは正しい位置だけです。先頭の区切りが `0` で始まる数（`0,123`・`000,000`）と、ちょうど `0` 以外の先頭の `0`（`¥007`・`0012`・`00.5`）は `invalid` です。区切りのない1〜3桁の整数（`0` を除く）に小数がちょうど3桁続く数（`1.000`・`12.500`）は、欧州式の3桁区切りと区別できないため `invalid` です。数は15桁まで（JSONの数値で正確に表せる範囲）です。範囲（`1,000〜2,000円`）・`以上`・`まで`・`約`・税率の併記（`10% ¥1,100`）・2つの数・`万`・`千` などの単位を含む値も `invalid` です。

金額・数値は、ラベルに単位がある場合と、文書のどこか（どのページでも）に単位の注記がある場合は変換せず `invalid` です。ラベルの単位は、桁（`十`・`百`・`千`・`万`・`十万`・`百万`・`千万`・`億`・`十億`・`百億`・`千億`・`兆`）で始まる括弧内（`単位` と `：`・`:`・`は` の後でもよい）、括弧の外の桁と `円`（`売上高千円`・`金額百円`）、またはラベルの中の単位の注記です（`売上高（千円）`・`売上高（十億円）`・`金額（百円）`・`金額（万円）`・`金額（単位は千円）`・`売上高（千円単位）`）。`金額（円）`・`金額（税込）`・`金額（税抜）`・`消費税（10%）` は単位ではありません。単位の注記は、空白を除き全角半角をそろえたうえで、次のどれかです。

- `単位` の後（`：`・`:`・`は` を挟んでもよい）の注記の本文を `）`・`。` か文末まで読み、`、`・`/`・`・`・`（` と、数字にはさまれていないカンマ（`,`・`，`。`1,000` の中のカンマでは区切りません）で区切った部分のどれかが次に当たる（`（単位：千円）`・`単位：万円`・`（単位は千円）`・`金額単位：千円`・`単 位：千円`・`（単位：1,000円）`・`単位：1000`・`（単位：1,000個）`・`（単位：100個、千円）`・`単位：個／千円`・`（単位：個，千円）`・`単位 円,千円`・`（単位：千円、税込）`）。`単位：円`・`（単位：個）`・`単位：1円`・`単位：円、個`・`（単位：円、税込）`・`単位：円（税抜）` は注記ではなく、`単位当たり`・`数量単位` のように区切りのない `単位` も注記ではありません。
  - `十`・`百`・`千`・`万`・`億`・`兆` で始まる。
  - 1以外の数で始まる。ただし `単位` の直前が文字（かな・漢字・英字のどれでも）で、数の後に下の数の単位が続く場合は、その語が数えるものを名指す数量とみなし、注記ではありません（`発注単位：100個`・`最小単位：10枚`）。直前の文字が何を表すかは確かめないため、`金額単位：1,000個` も数量とみなします。`単位：12本`・`（単位：12本）` のように直前が文字でなければ注記とみなします。
  - `（` の後の `単位`、または `：`・`:`・`は` の続く `単位` の後で、次のどれでもない（`（単位：ドル）`・`単位：千ドル`）。
    - `円` や数の単位（`個`・`件`・`枚`・`本`・`台`・`人`・`名`・`回`・`冊`・`箱`・`点`・`式`・`組`・`袋`・`缶`・`セット`・`日`・`時間`・`分`・`月`・`年`・`kg`・`g`・`t`・`m`・`cm`・`mm`・`l`・`%`）。前に数の1があっても、後に税の扱いが続いてもよい（`1円`・`円税込`）。
    - 税の扱い（`税込`・`税抜`・`税別`・`消費税込`・`消費税抜`・`消費税別`・`内税`・`外税`。後に `み`・`き` があってもよい）だけ。部分全体が税の扱いのときだけで、`税込千円` は注記です。
- `単位` の前に `十`〜`兆` の単位（と `円`）がある（`（千円単位）`・`百万円単位`）。
- `単位` を含まず、全体が括弧で囲んだ桁だけ（`（千円）`・`(百万円)`・`【万円】`・`（千）`）。`（円）`・`金額（千円）`・`（千円未満切捨て）` は注記ではありません（`金額（千円）` はラベルの単位として扱います）。

同じ行の隣り合う2つか3つの片をつなげたものも確かめるため、ランに分かれた注記（`（単位：` と `千円）`）も注記です。注記がどの表やページに及ぶかは判定できないため、注記より前のページや注記のないページの金額・数値も変換しません。文字列の項目は原文のまま返します。

日付は西暦のほか、和暦（令和・平成・昭和・大正、「元年」）と略記 `R8.11.8` / `H31/4/30` / `S55.3.1` をISO形式に変換します。元号の範囲外（例: 平成31年5月1日、令和元年4月30日）や、西暦と和暦の併記（例: `2026年(令和8年)11月8日`）・明治・曜日の不一致（`2026年11月8日(月)`）は `invalid` です。

レイアウトの候補には次の制限があります。

- 1つの片に「ラベル：」が複数ある（例: `TEL：03-1234-5678 FAX：03-1234-5679`）場合は、値と次のラベルの境目を決められないため分割せず、候補にもしません。
- 右の値が「ラベル：値」や「ラベル：」の片なら値にしません（例: `担当者` の右が `部署：経理部`）。
- 真下の候補が、右に自分の値を持つ次の行のラベルなら候補にしません（例: 値が空欄の `部署` の下の `役職`）。真下の値は、ラベルと値の右隣がともにないか、右隣どうしが同じ列にそろう場合だけ候補にします。右隣がともにない場合でも、すぐ上の行かすぐ下の行に、ラベルと左端のそろう片があり、その右に値があれば、ラベルの列とみなして真下を候補にしません（例: 値が空欄の `部署`・`役職` が続く場合）。
- 見出しや1列の一覧の下に2行以上のデータ行があれば、各行は列（`column`）の候補です。行の間隔は見出しから1行目までの間隔で測り、その列のセルが空欄でも隣の列がそろう行はデータ行として数えます。1行目がフォームのラベルである列はラベルの列とみなして候補にしません。
- 値は5行までで、超える場合は切り詰めずに候補から外します。

処理量には上限があります。1文書のラベル・値の候補は50,000件、作業量はレイアウト解析と照合の合計で200,000,000単位までです。単位は次の合計です: 原文のバイト数（レイアウト解析で片ごとに分類と寸法計算の2回（回転した片は読む向きの写しの作成でさらに1回）、照合で単位の注記の確認に空白の除去・全角半角の統一・照合の3回を、片ごとと、同じ行の隣り合う2〜3片をつなげたものごとに。注記が見つかればそこで止めます）、区切り記号のない片の先頭でラベルを探して読むバイト数（片ごとに1回、最大196バイト）、ラベルで始まる片の値でほかのラベルを探して読むバイト数（片ごとに1回）、フォームのラベルかを確かめた文字列のバイト数（値の中を確かめる分は、値の1バイトあたり最大10単位）、行の整理で並べ替えた比較の回数と片の数、探索で調べた行と片の数、候補に書き込む範囲ごとに1と片IDのバイト数、フォームのラベルと文書の各ラベルの比較で照合したバイト数、値の確認・正規化と結果への複製のバイト数、電話番号の候補の走査で読んだ文字数（1か所から最大25文字。それより長い数字と記号の並びは電話番号とみなさず、ハイフンでつないだ並びなら値が2つ以上あるとみなします）。レイアウト解析では、片の原文は候補に何回使われても読み直しません（空白だけで分ける候補のために、区切り記号のない片の先頭の最大196バイトと、ラベルで始まる片の値を、それぞれもう1回読みます。照合では候補ごとに値の原文を読み、その分を数えます）。真下や列の探索は1行あたり16片まで、値は5行まで、列は5行までです。1単位あたりの実時間は処理によって異なるため、作業量の上限は実行時間を保証しません。

上限を超えた場合は部分的な結果を返さず、`{"error":"layout_limit_exceeded"}` または `{"error":"fill_budget_exceeded"}` を出して終了コード4で終わります。CLIの `voltfill fill` は、コマンドの開始から30秒の期限を既定で設け、`--deadline-ms`（1〜600000）で変えられます。`--remote` の有無にかかわらず使え、期限を過ぎると `{"error":"fill_deadline_exceeded"}`（終了コード4）です。PDFの読み込みと解析（inspect）は `PdfLimits` の上限で止まり、期限では中断しません（その時間も期限に含めます）。期限が制限するのはJevへの送信より前のオフラインの処理だけで、上限や期限を超えた場合は結果を書かず、何も送りません。送信は `--execution-config` の `total_deadline_ms` などで制限します。ライブラリの既定（`vf_core::fill::FillLimits::default()`）は候補50,000件・200,000,000単位・期限なしで、`vf_core::fill::fill_with_limits` で上限と期限を指定できます。期限はレイアウト解析と照合の間、4,096単位ごと・項目ごと・長い原文を読む前に確認します。上限を指定しない `fill` は、超過時に全項目を `limit_exceeded` として返します。

テキスト片の数が資源制限の `max_items_per_page`（既定10,000）を超えるページは、PDFの解析で読み飛ばし、エラーにはしません。そのページにしかない項目は `not_found`、使えるテキストが1つも残らなければ全項目が `no_text` になります。読み飛ばしたページは `voltfill inspect` の `pages[].reason_codes` に `item_limit_exceeded` として出ます。[HTTPの `/v1/fill`](#http-server) も同じです。

<a id="fill-acroform"></a>

#### 入力欄つきPDF（AcroForm）

入力欄つきPDFでは、AcroFormの各フィールドの値（`/V`）もテキスト層と同じく原文として使います。値はPDF自身が持つデータで、生成も補完もしません。既定値（`/DV`）は使いません。XFAの中身は読みません。AcroFormは表以外の項目にだけ使い、表の項目（[下記](#fill-table)）には使いません。テキスト層の照合と同じ厳格な確定方針で、次のすべてを満たすときだけ `filled`（`method: "acroform"`）にします。満たさない規則は、項目の `acroform`（照合したフィールドごとの `field`（完全修飾名）・`kind`（`text` / `choice` / `checkbox` / `radio`）・`matched_by`（`name` / `alternate_name`）・`raw`・`display`・`issues`・`reasons`）の `reasons` にすべて示します。

| 規則 | 満たさないときの `reasons` |
|---|---|
| フィールドの完全修飾名の最後の部分名（`invoice.請求番号` の `請求番号`）か別名（`/TU`）が、フォームの `label` か `hints` と、テキスト層の条件1と同じ正規化のうえで等しい（部分一致・片側だけの補足は一致としない）。一致するフィールドがちょうど1つ | `several_fields` |
| そのフィールドがほかのフォーム項目にも一致しない（名前が `発行日`、別名が `支払期限` のフィールドは、両方の項目にあるときどちらにも使わない。別名の項目の型に値が合わない・選択欄で型のある項目に使えないなど、もう一方の項目でほかの規則を満たさない場合も同じ） | `field_matches_several_items` |
| XFAを持たない（XFAとAcroFormの両方を持つPDFは、XFA対応のビューアで別の値が表示されうる） | `xfa_present` |
| テキスト入力欄は `text`・`date`・`amount`・`number` に、選択欄は `text` にだけ使う（選択欄は書き出し値を `raw` にし、表示名は `display` に示す）。チェックボックスとラジオボタンは、フォームに対応する型がないため使わない | `kind_unsupported` |
| `/DV` 以外のフィールドの問題（`issues`）がない。正確に復号できない値、値を保存したパスワード欄、`.` を含む部分名、BOMのないPDFDocEncodingで0x80以上のバイトを含む値（`pdf_doc_high_bytes`。Shift_JISなど別の文字コードの文字化けの可能性）を含む | `field_issues` |
| `/V` がある | `value_absent` |
| `/V` が空や空白だけでない | `value_empty` |
| 選択が1つ | `several_values` |
| 選択欄では、書き出し値が `/Opt` の表示名とNFKCと空白の除去のうえで等しい（`/Opt [["13","東京都"]]` で `/V` が `13` のような、表示名と異なるコードは使わない） | `export_differs_from_display` |
| 値が1行（改行LF・CR・VT・FF・NEL・U+2028・U+2029を含まない） | `multi_line` |
| 値の文字数がフィールドの `/MaxLen` 以下 | `exceeds_max_len` |
| ウィジェット（表示欄）がある | `no_widget` |
| 非表示でないウィジェットがある | `hidden_widgets` |
| 非表示でないウィジェットのすべてにページと座標がある | `widget_without_rect` |
| ウィジェットの枠にかかる、使える横書き（ページ上で正立）のテキスト層の原文が、NFKCと空白の除去のうえで値（選択欄は書き出し値か表示名）と等しい。枠の中に印刷・平坦化された別の値や印刷されたラベルがあれば満たさない | `appearance_mismatch` |

表示の確認（`appearance_mismatch`・`appearance_unverified`）が確かめるのは、ページの内容としてテキスト層にある原文だけです。ウィジェット自身の表示（`/AP` の外観ストリーム）はテキスト層に入らないため確かめません。古い外観（`NeedAppearances` で再生成されていない表示など）がビューアで `/V` と違う値を表示していても検出しません。枠にテキスト層の原文がない場合（平坦化していない通常の入力欄）は確かめずに確定します。

テキスト層の照合との関係は次のとおりです。

- 確定できるAcroFormの値とテキスト層で埋めた値が等しい（日付・金額・数値は正規化値、文字列はNFKCと空白の除去のうえで）場合は、AcroFormの値で埋め、`evidence` にAcroFormとテキスト層の両方を入れます。
- 値が異なる場合は埋めずに `ambiguous`（候補なし）とし、`reasons` に `text_layer_conflict` を示します。
- テキスト層で埋まらなかった項目（`ambiguous`・`not_found`・`no_text`・`invalid`）は、確定できるAcroFormの値で埋め、テキスト層の候補は返しません。テキスト層で型に合わない値（`invalid`）が見つかっていても、名前で結び付いたAcroFormの値を優先します。
- 一致するフィールドが2つ以上ある場合は埋めません。ほかの規則を満たすものは配置 `widget`・`hold` なしの候補として先頭に返し、`--remote` でJevに選ばせられます。候補のラベルはフィールドの完全修飾名で、別名があれば ` / ` の後に続けます（`販売者.氏名 / 販売者の氏名`）。テキスト層で埋めた値は、それらがすべて同じ値のときだけ残し、異なれば `ambiguous`（候補なし）にします。
- 一致するフィールドが1つで、型の書式にだけ合わず、テキスト層に候補がない場合は `invalid` とし、AcroFormの値を `raw` と `evidence` に示します。それ以外の規則で確定できないフィールドは、テキスト層の結果を変えません。

AcroFormの `evidence` は、非表示でないウィジェットごとにページとウィジェットの枠（表示座標）を持ち、`precision: "widget"`（文字の座標ではなく入力欄の枠）、`acroform_field`（フィールドの完全修飾名）、`text`（値）を示します。原文片はないため `fragment_id` は空文字です。結果全体の `acroform` は、AcroFormを読めた場合 `{"status":"read","fields":件数,"xfa":"absent"|"hybrid"|"xfa_only"}`、読めなかった場合 `{"status":"unavailable","reason":…}` です。AcroFormのないPDFと、フィールドもXFAもないAcroForm（`/AcroForm <<>>` など）では、結果全体にも項目にも `acroform` は付かず、出力はテキスト層だけの照合と同じです。XFAだけのフォームは、値がXFA側にありうるため `"fields":0,"xfa":"xfa_only"` を示します。

AcroFormは、PDFの解析（inspect）と同じ読み込みから `vf_source::acroform::AcroFormLimits` の上限で読みます。入力サイズとページ数は `PdfLimits` と同じで、ほかは既定値（フィールドとウィジェット10,000件・注釈50,000件・入れ子の深さ32・復号した文字列4 MiB）です。上限を超えた場合・暗号化を解除して読み込んだPDF・不正なフィールドの木では、AcroFormを使わずテキスト層だけで照合し、`reason`（`limit_exceeded`（`limit` に上限名）・`encrypted`・`invalid_field_tree` など）を示します。照合の作業量（名前と値の正規化・比較・複製のバイト数、単位の注記の確認、枠の原文の選択）はテキスト層と同じ作業量の上限と期限に含めます。確かめたのは合成のPDFだけで、評価セット（下記）にはAcroFormのケースはまだありません。

表の項目以外では、区切り記号のない値・真下の値・表や一覧・複数行の値・複数のランに分かれた可能性のある値は、値を入れずに `hold` 付きの候補として返します。1つの片の中の「ラベル 値」は、`no_delimiter` だけが理由になる場合に限って候補として返し、値が2行以上・値が2つ以上・すぐ右に区切り記号のない片がある・型の書式に合わない・値にほかのラベルを含む場合は候補にもしません（上記）。縦書きフォントによる縦書きも候補になりません。対応していないレイアウトは誤った値ではなく候補か空欄になる、というのが確定方針の狙いですが、確かめたのは合成の評価セットだけで、実文書で誤入力がないことは保証しません。既知の限界として、`ラベル：` の同じ行の4em以内の右に区切り記号のない別のラベルがある記入前の様式（`氏名：` のすぐ右の `生年月日` で、フォームに `生年月日` がない場合）は、そのラベルを値として埋めます（4emより離れていれば位置だけの候補です）。また、続きの行が上記の位置から外れる値（例: 値の推定開始位置より大きく右から続く行）は1行の値として扱います。空白だけで分けた値では、折り返した文の次の行がフォームのラベルと空白で始まると（`備考 お支払いは` の次の行が `合計 金額の確定後に…`）、値はその手前で切れ、`お支払いは` が候補になります。オフラインでは埋めませんが、`--remote` ではJevがこの候補を選ぶことがあります。スキャンPDFのOCRは行いません。結果は評価専用です。

90°・180°・270° 回転した文字（例：90°回転した欄の「請求番号：INV-001」）は、その文字の読む向きで行にまとめ、横書きと同じ規則でラベルと値の候補を作ります。区切り記号で結び付く距離（4em以内）、値の後に同じ行の片が続く場合の途中で切れている可能性、真下と列の判定も読む向きで同じように適用し、確定方針も横書きと同じです。向きの違う片どうしは組み合わせません。座標は回転していても表示上のページの座標（左上原点）で、片の一部の推定座標は読む向きに沿って求めます。回転した片は向きごとに読む向きへ回した写しで解析し、候補数・作業量・期限の上限はすべての向きを合わせて数えます（写しの作成と座標を戻す処理も作業量に含めます）。ただし、次の回転した片は使いません。

- PDF解析ライブラリ（pdf-inspector）は、横書きの文字なら1語ずつ描かれていても半角幅（0.5 em）以内の隣どうしを1つの片につなぎますが、回転した文字はつなぎません。そのため、同じ行で0.5 em以内に隣り合う回転した片は1つの語句の一部とみなし、ラベルにも値にもしません（つないで読むこともしません）。1語ずつ描かれた回転した欄は `not_found` になることがあります。
- pdf-inspector が上付き・下付き文字として隣の片とつないだ可能性がある片（上付き・下付きの数字を含む片、ベースラインのずれを持つ片）があるページでは、そのページの回転した片をすべて使いません。

また、区切り記号（`：`・`:`）だけの値は候補にしません。鏡文字になる文字の行列（`[0 1 1 0]`・`[0 -1 -1 0]`・`[1 0 0 -1]` など）は pdf-inspector から判別できないため検出せず、報告された向きのまま読みます。この場合、片の一部の推定座標が片の反対側の端に来たり、ラベルと値の順が逆になったりすることがあります。回転した文字の読み取りは合成PDFでのみ試験しています。

次のページはページ全体の文字を使いません：縦書きフォント（WMode 1）を含むページ、斜めの文字が1つでもあるページ（「見本」などの斜めの透かしを含む）、縦の文字が主でページの向き（`/Rotate`）と合わないページ。これらの文字は値にもラベルにも使わないため、項目は `not_found` になります（使える文字が文書に1つもなければ `no_text`）。横書きフォントで1文字ずつ縦に並べた縦書きは検出しません。縦書きフォントによる本来の縦書きへの対応は、pdf-inspector 側の対応を待って行う予定です。

<a id="fill-table"></a>

**表の項目（明細）**: `type: "table"` の項目は、見出し行の下の明細行を行の配列として返します。

```json
{"id": "items", "label": "明細", "type": "table", "columns": [
  {"id": "name", "label": "品名", "hints": ["品目"]},
  {"id": "qty", "label": "数量", "type": "number"},
  {"id": "amount", "label": "金額", "type": "amount"}
]}
```

列は `id`・`label`・`type`（`text` / `date` / `amount` / `number`、既定 `text`）・`hints`（見出しの別名、16個まで）で、1項目に1〜16列です。列の `id` は重複できず、全列の `label` と `hints` は正規化のうえで互いに異なる必要があります（1つの見出しのセルが2つの列に一致しないように）。表の項目自体の `label` は照合に使わず、項目に `hints` は付けられません。条件に合わないフォームは `invalid_form` です。

表を確定する（`filled`、`method: "table_match"`）のは、次をすべて満たす場合だけです。それ以外は値を入れず、読んだ表を `hold` 付きの候補として返します。

1. **見出しが完全一致する**: 文書の1つの行に、フォームの全列について、列の `label` か `hints` のどれかと正規化（通常の項目と同じ。先頭の `ご`・`御`・`お` は無視し、括弧内の補足まで等しいこと）のうえで等しい片がある。片全体が等しいことが必要で、部分一致や片方だけの補足（文書の `商品名` とフォームの `品名`、`金額（税込）` と `金額`）は一致しません。区切り記号の付いた片（`品名：`）はラベルで、見出しのセルにはしません。見出しの行に、フォームにない列があってもかまいません。そのような行が文書に2つ以上ある、または1つの列が同じ行の2つの片に一致する（表が横に並ぶ場合など）ときは `ambiguous` です。
2. **行が列にそろう明細行**: 見出しの下の各行で、すべての片が、見出しのちょうど1つのセルの列にそろう（左端・右端・中央のどれかの差が1行の高さ以内、または横に重なる）。1つの列に2つの片がある、複数の列にまたがる片・どの列にもそろわない片がある、セルが1列だけ（折り返したセルと1セルの行を区別できない）、のどれかに当たる行は不規則です。行の間隔（見出しと1行目、続く行どうしのベースラインの距離の、上側の中央値）の3/4より上の行に近い行は、複数の列で同時に折り返したセルの続きとみなし不規則です。各行は明細行であること: フォームに型のある列（日付・金額・数値）があればそのどれかにセルがあり、さらに見出しの1列目かフォームの文字列の列のどれかにセルがあること（備考の行、一覧にないラベルの合計系の行、横に並ぶ別の表だけの行は明細行ではありません）。見出しの行の片は2〜32個で、区切り記号の付いた片を含みません。空欄のセルは `null` です。回転した片だけの行（余白の `CONFIDENTIAL` などの印）は、表の範囲（見出しの左端から右端まで、見出しの上端から、行を読んでいる間はページの下端まで、行が止まった後は最後の明細行の下端まで）に重ならなければ無視し、重なれば不規則です（横書きの片と同じ行にある回転した片も不規則です）。
3. **行が閉じる**: 行は、合計系のラベルの行、列にそろう片がない行（`備考：…` など）、行の間隔を超える空白、ページの最後の行のどれかで終わります。合計系のラベルは、締めの合計（`合計`・`総計`・`総額`・`合計金額`・`税込合計`・`税込金額`・`税込総額`・`請求金額`・`請求額`・`今回請求額`・`差引請求額`・`支払金額`・`見積金額`・`以下余白`・`以上` など）と小計（`計`・`小計`・`税抜金額`・`消費税`・`消費税額`・`税額`・`内消費税`・`源泉徴収税額`・`値引合計` などと、`…小計`・`…合計`・`…%対象`・`…税率対象` で終わるもの）の固定の一覧で、括弧内の補足と末尾の税率（`消費税 10%`）と、語の途中を含む `御` と漢字の前の `ご`・`お`（`今回御請求額` = `今回請求額`。`りんご` の `ご` は残す）を除いて比べ、`合計：¥2,970` のような区切り記号付きの片はラベルの側で比べます。合計系のラベルの行は、どれかの片が合計系のラベルで、最初の合計系のラベルより左に列にそろう片が2つ未満の行です。合計系のラベルはその金額より左にあるため、左に列にそろう片が2つ以上あれば明細行かもしれない行（明細行の右に合計のブロックが並ぶ `ぶどう 1 ¥900 … 合計 ¥1,700`）として不規則にします。行全体が明細行として読める行も不規則にします: 見出しの1列目・フォームの文字列の列・フォームの日付と数値の列・フォームにない列（フォームの金額の列にもそろう片を除く）にそろう片（合計系のラベルを除く）と、フォームの日付・数値・金額の列にあり1列目と文字列の列にない合計系のラベル（明細のセルの位置を占める）が2つ以上あり、そのどれかが1列目か文字列の列にある行です。フォームの金額の列の金額（合計系の行にもある）と、1列目・文字列の列・フォームにない列・どの列にもそろわない位置の合計系のラベル（行の名前）は数えません。左の余白の `合計` の右に `ぶどう 1 ¥900` が並ぶ行（フォームに数量の列がなくても）や、数量の列に `小計` がある `ぶどう 小計 ¥900` は不規則です。フォームにない列（単価など）の `小計` の左の1列目の注記（`※は軽減税率の品目`）や、1列目の `合計` の右の点数（`合計 5 ¥800`）は合計系の行です。1行目は見出しから1行の高さ以内、以降は見出しから1行目までの間隔（1行の高さ以上）に0.5行の高さを足した間隔以内に続く行です。空白の後の行が明細行か不規則な行の場合は不規則です（空白の後の1列目だけの見出しを含む）。合計系の行・列にそろわない行・空白の後の列にそろわない行で止まったときは、その下の行も、上の行からこの間隔以内に続くまとまりごとに読みます。読むのは、止まった行のまとまり、合計系の行で始まるまとまり、空白をはさんだ次のまとまり1つ（締めの合計を読んだ後は除く。別の表が続くことがあるため）です。読んだ行に明細行か2列以上に片がある不規則な行があれば不規則です（グループごとの小計の後に明細が続く、明細の間に見出し・`納品日：…`・段組みの本文の行がある、など）。行は次のページに続けません。後ろのページに原文の片（文字化けした片を含む）がある場合は、読んだ合計系の行に締めの合計があるときだけ表が閉じ、小計だけ・列にそろわない行・空白・ページの最後で終わるときは続きがあるとみなします。同じページに `次頁`・`次ページ` などがある場合と、原文の片がある次のページに `前頁`・`前ページ`・`繰越` などがある場合（`（前頁より続く）`）も、締めの合計があっても続きがあるとみなします。行は100行までです。
4. **セルが型に合う**: 日付・金額・数値の列の空欄でないセルは、値全体が通常の項目と同じ書式（下の表）に一致すること。文書のどこか（どのページでも）に単位の注記（`（単位：千円）`・`（千円）` など）がある場合の表と、単位を含む見出し（`金額（千円）`）の列の金額・数値は変換しません。1つでも合わなければ表全体を確定しません。
5. **型のある列がある**: フォームの列に日付・金額・数値の列が1つ以上あること。文字列の列だけでは、直下の別の表の見出しや行を明細行と区別できないため確定しません。

| `hold`（表の項目） | 理由 |
|---|---|
| `irregular_table` | 不規則な行・明細行でない行がある、止まった行の下に明細行がある、または見出しの行の片が2〜32個でないか区切り記号の付いた片を含む（条件2・3） |
| `too_many_rows` | 行が100行を超える（条件3） |
| `continues_on_next_page` | 表が次のページに続く可能性がある（条件3） |
| `invalid_cell` | 型の書式に合わないセルがある（条件4） |
| `untyped_table` | フォームの列が文字列だけ（条件5） |

`hold` は上の表の順で最初に当たったものです。

- `filled`: `rows` と `evidence` を返します。`rows` は行ごとに列の `id` をキーとするオブジェクトで、セルは `raw`（原文）・`value`（文字列の列は原文、日付・金額・数値の列は正規化値）・`evidence`（前後の空白を除いた片全体）、空欄は `null` です。`evidence` は見出しのセル（フォームの列の順）です。少なくとも1行が必要です。
- 確定できない表は `candidates` に、`hold`（ほかの表と区別できない場合はなし）・それまでに読んだ `rows`（明細行でない行の前まで）・見出しの `evidence` として文書の順に最大5件返します。`status` は、全列がそろう見出しの行がない、または見出しの下に行がなく閉じている場合は `not_found`、見出しの行が1つで `invalid_cell` なら `invalid`、それ以外は `ambiguous` です。
- 表の読み取りも、通常の項目と同じ作業量の上限と期限に含みます。単位は主に、見出しの候補ごとに、その下で読んだ行の数と片の数の2倍（回転した片だけの行かの確認と読み取り）、見出しの片の原文のバイト数、行の片の原文の1バイトあたり2単位（合計系のラベルと区切り記号の確認）、片と比べた列の数、行の間隔の計算に1行あたり1、合計系のラベルの行を明細行として読めるか確かめる分（片ごとに1と原文の1バイトあたり1、片と比べた列の数）、セルと見出しごとの範囲（原文の1バイトあたり2単位と、1と片IDのバイト数）です。
- 通常の項目は表のセルを値にしません（列の値は従来どおり `geometric_only` の候補止まり）。列の `label`・`hints` は、通常の項目の値がフォームのラベルとみなされる語と、空白だけで分ける「ラベル 値」のラベルと値の中のラベルの判定に加わります（見出しの行 `品名 数量 単価 金額` が1つの片でも、通常の項目の候補になりません）。

既知の限界: 見出しのセルが複数の片に分かれている（`品` と `名`）、または2行にわたる見出しは見出しとみなさず `not_found` です。合計系のラベルは固定の一覧で、一覧にない語の行（`送料`・`値引き`、また `前回請求額` など）は、明細行の条件を満たせば明細行として読みます。合計系のラベルより左に列にそろう片が2つ以上ある行は、件数の欄（`点数 5 合計 ¥800`）でも不規則として確定しません。また、合計系のラベルの行で数える片が1つだけの明細行（左の余白の `合計` の右に数量のない `ぶどう ¥900`）は、1列目の注記と合計の行と区別できないため合計系の行として表を閉じ、その行を落とした前の行を確定します。次のページの `前頁`・`繰越` はページのどこにあっても（先頭でなくても、`前月繰越` のような別の意味でも）前のページの続きとみなし、確定しません。逆に、明細行の1列目かフォームの文字列の列のセルが合計系のラベルと等しいと、その行で表が終わります（下に明細行がなければ、その行より前の行を確定します）。複数の列で折り返した続きの行のうち、行の間隔の3/4以上離れたもの（行間の詰まった表）は検出しません。また行が2行だけの表で、見出しから1行目までの間隔が行どうしの間隔の4/3倍を超えると、2行目を折り返しとみなして確定しません。止まった行の下で読むのは空白をはさんだ次のまとまりまでのため、2つ目の空白の先の明細行と、締めの合計の後に空白をはさんで続く明細行は検出しません。括弧で囲んだ桁は片全体がそれだけの場合に限り単位の注記とみなし、題名の一部（`売上明細（千円）`）は注記とみなしません。テキスト層のない後ろのページ（スキャン）は、続きのページとして数えません。確かめたのは合成の評価セットだけです。

<a id="fill-remote"></a>

`--remote` を付けると、`ambiguous` の項目（表の項目を除く）だけをJevに送り、その項目の候補から選ばせます。表の項目は送らず、そのまま返します。接続先とキーは `run --remote` と同じく必要です（[実APIの利用](#environment)）。`--remote` なしでは認証情報を読まず、結果も変わりません。

```sh
voltfill fill input.pdf examples/forms/invoice.json --remote -o result.json
```

- 送るのは項目のラベル・型・別名と、選択肢にした候補ごとのページ・原文のラベルと値だけです。ページ画像・前後の行・ほかの項目は送りません。候補の文は選択対象の文書データで指示ではないと、要求に明記します。
- 選択肢は、選べば1つの値になる候補と `none` です。満たさなかった条件（`holds`）がすべてラベルか結び付きの理由（`partial_label`・`one_sided_qualifier`・`geometric_only`・`no_delimiter`）である候補だけを選択肢にします。`holds` にそれ以外の理由（`multi_line`・`split_value`・`several_values`）を含む候補は、最初の理由（`hold`）がラベルや結び付きでも、選んでも1つの値にならないため選択肢にせず、送りもしません。日付・金額・数値の項目で正規化値のない候補も同じです。キーは `candidates` での位置（`c0`・`c1`…）のままで、選択肢にしなかった候補のキーは不正な回答です。選択肢にできる候補がない項目は送らず、`ambiguous` のまま候補を返します。
- 選ばれた候補が確率の単独最大で、確率の合計が1のときだけ `filled`（`method: "jev_choice"`）にし、`raw`・`value`・`evidence` はその候補の原文から取ります。`none` が単独最大なら `not_found`、同率・不正な回答（確率の合計が1でないものを含む）・送信失敗では `ambiguous` のままです。送った項目は `candidates` を残します。
- 結果には `model`・`assist`（項目ごとの質問ID・`outcome`・選ばれたキー）・`usage`・`jev_responses` が加わります。`jev_responses` は再試行・エラー・不完全な本文を含む全試行の受信本文です。
- `outcome` は、回答を得た場合が `selected`・`none_selected`・`not_unique_maximum` です。失敗には `answer_invalid`・`request_failed`・`budget_exhausted`（上限に達したか予算が停止していて、そのバッチかその再試行を送らなかった）・`usage_exceeded_budget`・`deadline_exceeded`・`request_too_large`・`cancelled` があります。`usage_exceeded_budget` は、受信して解析できた回答の使用量が予約か費用上限を超えた場合です。その回答は使わず（本文は残します）、以降のバッチも送りません。`cancelled` はライブラリの呼び出し側が中止させた場合で、CLIからは発生しません。
- `--model`・`--max-attempts`・`--execution-config FILE` が使えます（`--deadline-ms` も使えますが、制限するのは送信前のオフラインの処理だけです）。バッチは1件ずつ送ります。送信回数（`max_requests`）・費用・本文量・期限の上限は全バッチと再試行の合計に適用します。試行回数（`--max-attempts`）はバッチごとで、各試行も送信回数に数えます。トークンの上限は1試行ごと（`input_tokens_per_attempt`）と1秒あたり（`input_tokens_per_second`）です。
- 送った項目がすべて失敗で終わった場合も、全受信本文を含む結果を書き出してから終了コード4（`fill_assist_all_failed`）を返します。書き出せないと事前に分かる出力先は送信前に止めます（[出力先](#output)）。項目が `ambiguous`・`not_found` のまま残っても終了コードは0です（送った項目がすべて `not_unique_maximum` の場合も含みます。`--remote` なしの `fill` と同じく、各項目の `status` で確認します）。
- 模擬応答でのみ試験しており、実APIでの精度は未測定です。confidence・確率は校正済みの正答確率ではありません。

`fill` の終了コードは次のとおりです。終了コード4は、結果を書く前の失敗と、結果を書いた後の `fill_assist_all_failed` があり、標準エラーのJSONの `error` で区別します。

| 終了コード | 結果 | 主な `error` |
|---|---|---|
| 0 | 書く | — （`ambiguous`・`not_found` の項目が残る場合も含む。各項目の `status` で確認） |
| 2 | 書かず、送らない | `invalid_arguments`・`invalid_deadline`・`invalid_form`・`input_read_failed`・`input_too_large`、`--remote` では `invalid_model`・`invalid_execution_config`・`api_key_required` など |
| 4 | 書かず、送らない | `pdf_inspection_failed`・`layout_limit_exceeded`・`fill_budget_exceeded`・`fill_deadline_exceeded`、`--remote` では `transport_setup_failed` |
| 4 | 全受信本文を含めて書く | `fill_assist_all_failed`（送った項目がすべて失敗） |
| 5 | [出力先](#output)を参照 | `output_*`・`input_overwrite_refused` など |

画像フォールバック（計画中・`fill` では未使用）の部品として、モデルが示した囲み（box）の内側の原文片を返す `vf_source::select::in_box` があります。対象は横書きの片だけで、回転した片は囲みの内側にあっても返しません。片の一部を囲む場合は、レイアウト解析がその片の中の区切り記号でラベルと値を結び付けた（`binding: "delimiter"`）「ラベル：値」の分割位置でだけ切り出し、ラベルと値を分けられない片（`TEL：…　FAX：…`、`Total = 12000` など）は値にしない役割（`mixed`）で返します。作業量と期限は `vf_source::select::in_box_within` でレイアウト解析・照合と同じ予算（`Budget`）に計上できます。

接続先とキーを設定し（[実APIの利用](#environment)）、PDFと抽出定義を渡します。

```sh
voltfill run input.pdf examples/legacy/text-form.json --remote -o result.json
```

既定はText方式です。全オプションは `voltfill --help` を参照してください。

| 方式 | 動作 | スキーマ例 |
|---|---|---|
| `text` | 原文の候補から選択 | [Text](examples/legacy/text-form.json) |
| `vision` | 画像のBoxを原文に対応付け | [Vision](examples/legacy/vision-form.json) |
| `hybrid` | 文字候補とBoxを照合 | [Hybrid](examples/legacy/hybrid-form.json) |

既定モデルは `jev-1.14.0`（`--model ID` で変更）。Vision／Hybridは1.14.0以降のバージョン指定IDと[レンダラー](#rendering)が必要です。

<a id="results"></a>

## 抽出結果

結果は `fields`・`evidence`・`usage`・`jev_responses` です。部分失敗でも値を保持するため、`status`・`reason_codes` を確認してください。再試行・エラーの受信本文も残し、未受信・不完全なら `body_complete: false` です。

原文・座標・型・validatorを検証し、既定ではconfidenceで足切りしません。結果は評価専用（`evaluation_only: true`）で、confidenceは校正済みの正答確率ではありません。

<a id="output"></a>

## 出力先（`-o` / `--output`）

`-o` を付けたコマンド（`fill`・`inspect`・`run`／`extract`）は、設定ファイル（`--config`・`--execution-config`・`--resource-config`）を読んだ後、PDF・フォーム・スキーマ・模擬応答・APIキーを読む前で送信前に、出力先を確かめて同じディレクトリに一時ファイル（`.voltfill-<PID>-<番号>.tmp`）を作ります。次の場合は終了コード5で止まり、何も送りません。

| エラー | 出力先 |
|---|---|
| `invalid_output_path` | 空、または `/`・`.`・`..` で終わるパス |
| `symlink_output_refused` | シンボリックリンク |
| `output_is_directory`・`output_not_regular_file` | 既存のディレクトリ、通常ファイル以外 |
| `input_overwrite_refused` | 入力・設定ファイル・ネイティブライブラリ・`VOLTFILL_JEV_API_KEY_FILE` と同じファイル（キーファイルはパスだけを比べ、中身は読みません） |
| `output_directory_not_found`・`output_not_writable` | ディレクトリがない、書き込めない |
| `output_not_accessible` | 状態を確かめられない（名前が長すぎる、シンボリックリンクが循環している、ディレクトリを検索する権限がないなど） |

結果は一時ファイルに書いてから出力先へ名前を変えて置き換えます。置き換えはリンクをたどらないため、実行中に出力先へ置かれたシンボリックリンクはそれ自体が置き換わり、リンク先は変わりません。結果を書き始める前に止まった場合（送信前のエラーなど）、一時ファイルは削除します。

事前の確認ですべての失敗が分かるわけではありません。変更不可フラグ（`chflags uchg` など）の付いた出力先や、スティッキービット付きディレクトリにあるほかのユーザーの出力先は、送信後の置き換えで `output_rename_failed` になります。結果を書き込めない場合（`output_write_failed`。ディスク不足など）と置き換えられない場合（`output_rename_failed`）は、どちらも終了コード5で、受信本文を含む結果を次の順に残します。

1. 置き換えに失敗し、一時ファイルが結果全体を持ったまま残っていれば、それを残します。
2. そうでなければ（書き込みの失敗、実行中に一時ファイルや出力先のディレクトリが消えた場合など）、出力先のディレクトリ、次に作業ディレクトリに新しい一時ファイルを作り、結果全体を書き直します。
3. どのファイルにも書けなければ、標準エラーに `{"error":"<エラー>","result":<結果>}` という1つのJSONで書きます。結果のバイト列は変えません。`-o` 指定時のログは標準出力なので、標準エラーには混ざりません。

1・2では、存在して結果全体の長さを持つと確かめたファイルだけを、エラーのJSON（ログが有効ならエラーのログ）の `output_kept` に示します。3では `output_kept` を付けず、ログが有効ならエラーのログに `result_on_stderr`（標準エラーへの書き込みが成功したか）を付けます。標準出力には切り替えません。標準エラーを `/dev/null` に向けている場合、3の結果は残りません。書き込みに失敗した一時ファイル（空または途中まで）は受信本文を含みうるため削除せず、`output_kept` にも示さずに残します。シグナル（`SIGTERM`・Ctrl-C など）で強制終了した場合も、権限0600の `.voltfill-<PID>-<番号>.tmp`（空、書き込み中なら途中まで）が残ることがあります。

## 設定

```sh
voltfill run --config examples/legacy/voltfill.yaml
```

[YAML例](examples/legacy/voltfill.yaml)は固定回答で無送信です。TOML・JSONも使えます。優先順位は **CLI → 指定ファイル → 環境変数 → 既定値**。`--config` 省略時は `VOLTFILL_CONFIG` を使います。相対パスの基準は、ファイル内なら設定ディレクトリ、それ以外は作業ディレクトリです。

送信制限の[設定例](examples/legacy/execution-config.json)は既定値一覧ではありません。`--execution-config FILE` / `--resource-config FILE` は `execution` / `resources` 全体をJSONで置き換えます。資源制限はPDF解析を隔離せず、費用予約も入力の推定で請求上限ではありません。

ログは既定オフ（`--log-level`）で、1行1件のJSONを出力します。CLIは標準エラー、`--output` 指定時とサーバーは標準出力です。本文・認証情報・HTTPヘッダーは出しません。

<a id="environment"></a>

### 実APIの利用

接続先は `VOLTFILL_JEV_ENDPOINT`（信頼できるHTTPS）、キーは `VOLTFILL_JEV_API_KEY` / `VOLTFILL_JEV_API_KEY_FILE` の一方だけで指定します。設定ファイルにキーは書けず、`.env` も読みません。送信には `--remote` / `remote: true` が必須です。

<a id="rendering"></a>

### 描画

Vision／Hybridはレンダラーのビルドと選択が必要です。自動切り替え・自動取得・OCRは行いません。

```sh
cargo install --path crates/vf-cli --locked --features hayro
voltfill run input.pdf examples/legacy/vision-form.json --remote --strategy vision --renderer hayro
```

Hayroはネイティブライブラリ不要です。PDFiumは利用側で用意し、`--features pdfium`、`--renderer pdfium` と `--pdfium-lib` / `VOLTFILL_PDFIUM_LIB_PATH` の絶対パスで指定します。描画倍率は既定1.5ピクセル/PDF単位（`--pixels-per-point`）です。

<a id="http-server"></a>

## HTTPサーバー

```sh
voltfill serve --mock examples/legacy/text-mock.json --listen 127.0.0.1:3000
```

`POST /v1/extract` はmultipartの `pdf`・`schema` と任意のJSON `options`（`strategy`・`model`）、`GET /health` はヘルスチェックです。モックは形式確認用で、精度評価には使えません。実APIでは `--remote` で起動し、Vision／Hybridは `--allow-images` とレンダラーを指定します。

```sh
curl --fail-with-body --silent --show-error http://127.0.0.1:3000/v1/extract \
  --form 'pdf=@input.pdf;type=application/pdf' \
  --form 'schema=@examples/legacy/text-form.json;type=application/json'
```

`POST /v1/fill` は[フォーム入力](#fill)のHTTP版（`--remote` なしの `voltfill fill`）で、multipartの `pdf` と `form`（`voltfill fill` と同じフォーム項目のJSON）を受け取り、`voltfill fill` と同じ形の結果JSONを `200` で返します。Jevには送信せず、描画もしないため、`--mock` / `--remote` のどちらで起動しても同じ動作です。

```sh
curl --fail-with-body --silent --show-error http://127.0.0.1:3000/v1/fill \
  --form 'pdf=@input.pdf;type=application/pdf' \
  --form 'form=@examples/forms/invoice.json;type=application/json'
```

処理量の上限は `voltfill fill` と同じ（候補50,000件・作業量200,000,000単位）です。期限は、アップロードの読み込みとフォームの検証が終わって処理を始めてから30秒で、変更できません。PDFの解析は期限で中断しませんが、その時間も期限に含めます。上限や期限を超えた場合は部分的な結果を返しません。`max_items_per_page` を超えるページは読み飛ばし、そのページの項目は `not_found` か `no_text` になります（[フォーム入力](#fill)と同じ）。

エラーは `{"error": "<code>", "jev_responses": []}` で返します。表はおおよそ確認する順です。

| HTTP | `error` | 条件 |
|---|---|---|
| 401 | `unauthorized` | APIキーを設定していて、`Authorization: Bearer <key>` がないか一致しない |
| 403 | `browser_authentication_required` | APIキーが未設定で、`Origin` 付きの要求 |
| 429 | `server_busy` | 抽出かフォーム入力を実行中（`Retry-After: 2`） |
| 400 | `invalid_multipart` | multipartでない（`Content-Type` が違う、boundaryがない） |
| 400・413・500 | `invalid_or_oversized_upload` | multipartを読めない。400は形式の誤り、413は本文全体がアップロード上限（PDFの `max_bytes` ＋1 MiB＋128 KiB）を超えた場合、500はそのほかの読み込みの失敗 |
| 400 | `unknown_or_duplicate_part` | `pdf`・`form` 以外のpart、または同じpartが2つある |
| 413 | `part_too_large` | partが上限を超えた（`pdf` は資源制限の `max_bytes`、`form` は1 MiB） |
| 408 | `upload_timeout` | アップロードが `--upload-timeout-ms`（既定30000）内に終わらない |
| 400 | `missing_pdf_or_form` | `pdf` か `form` がない |
| 400 | `invalid_form` | フォームのJSONが不正 |
| 400 | `pdf_inspection_failed` | PDFを解析できない（暗号化・ページツリーの不正を含む） |
| 413 | `input_too_large` | ページ数が資源制限の `max_pages` を超えた |
| 413 | `layout_limit_exceeded` | ラベル・値の候補が50,000件を超えた |
| 413 | `fill_budget_exceeded` | レイアウト解析と照合の作業量が上限を超えた |
| 504 | `fill_deadline_exceeded` | 処理の開始から30秒を過ぎた |
| 500 | `worker_failed` | 処理中の内部エラー。Jevには送信していないため、受付は止めません |

認証は `VOLTFILL_SERVER_API_KEY` / `VOLTFILL_SERVER_API_KEY_FILE` の一方を設定し、`Authorization: Bearer <key>` を送ります。未設定のループバックでは任意、非ループバック待ち受け・`Origin` 付き要求では必須です（`/v1/extract`・`/v1/fill` 共通）。VOLTFILLはHTTPのため、別マシンからはTLSプロキシを使います。

抽出とフォーム入力は合わせて同時1件で、実行中は `Retry-After` 付き `429 server_busy` です。抽出はJevの送信間隔の待機中も `429`、送信停止中は `503 remote_paused_unknown_outcome` で、Jevに送信しないフォーム入力はこの2つの影響を受けません。`--reuse-document`（既定オフ）は直前1件の文書をTTL（`--reuse-document-ttl-ms`、既定60000 ms）までメモリに保持して再利用します。内容が要求後も残るため単一テナント向けです。

<a id="evaluation"></a>

### フォーム入力の評価セット

フォーム入力（fill）を合成PDFで評価します。フォントファイルなしで日本語（BMP外の文字を含む）のテキスト層を持つPDFを生成し（Type0・Identity-H、ToUnicode付き、グリフ非埋め込み）、ケースごとに項目の期待値（原文と正規化値）または「空欄のまま」と照合します。ネットワークは使いません。

```sh
cargo test -p vf-core --test eval -- --nocapture
```

| 指標 | 意味 |
|---|---|
| `correct` | 期待どおりの原文・正規化値で埋めた |
| `wrong` | 値を期待した項目を、記録にない別の値で埋めた |
| `unexpected` | 空欄を期待した項目を、記録にない値で埋めた |
| `known` | 項目に記録した既知の誤入力（`known_wrong`）と同じ原文・正規化値で埋めた |
| `empty` | 値を期待したが埋めなかった |
| `abstain` | 空欄を期待し、空欄のままだった |

ケースごとの表に、対応済み・未対応のケース別の小計と合計を添えます。既知の誤入力も誤入力の件数（`wrong fills`）に含めます。

表の項目は期待値を `rows`（行ごとに全列の `id` をキーとし、空欄は `null`、それ以外はセルの原文 `raw` と、型のある列の正規化値 `value`）で書きます。表の項目は1件として数え、すべての行とセルが一致したときだけ `correct` です。見出しとセルのEvidenceも、下記の値のEvidenceと同じく原文片の正確な切り出しで生成時の位置と一致することを確かめます。

次のいずれかでテストは失敗します。

- 値を期待した項目を別の値で埋めた、または空欄を期待した項目を埋めた。項目の `known_wrong`（`{"status": "filled", "raw": …, "value": …, "reason": …}`）と原文・正規化値が完全に一致する出力だけは除く
- `known_wrong` を記録した項目の出力が記録と変わった。直った場合も別の誤った値になった場合も失敗にし、ケースの更新を求める
- 対応済みのケースで、期待した値が空欄になった、または空欄の状態（`not_found`・`ambiguous`・`invalid`）が期待と違う
- 空欄を期待した項目に書いた、最上位の候補の確定できない理由（`hold`。理由がなければ `"none"`）、すべての理由（`holds`）または原文（`candidate`）が期待と違う。オフラインで確定しない値は、正しい値が最上位の候補であることを `candidate` で確かめます
- 埋めた値と `invalid` の原文のEvidenceが、原文片の正確な切り出しでない、期待した値の場合に期待したランを指さない、生成時に配置した位置と0.05pt以内で一致しない、または `precision` が片全体なら `run`・一部なら `estimated` でない
- 埋めていない項目が正規化値を持つ、または `invalid` 以外の項目が原文やEvidenceを持つ
- 対応済みのケースで、抽出した片がランと1対1でない。ランの結合を確かめるケース（例: 数字が別のランに分かれた金額）は、期待する片の原文を `fragments` に書きます

失敗にしないのは、`known_wrong` と完全に一致する出力（`KNOWN` として理由とともに表示）と、未対応のケース（オフラインでは候補止まりの区切り記号のない「ラベル 値」、行間の詰まったラベル表でフォームが一部の項目だけを持つ場合）で空欄のままの項目だけです。未対応のケースは、正しく埋まっていた項目（`currently_correct`）が空欄に戻ったとき、また全項目が合格したときに注記（`NOTE`）を出します。ケースは[tests/eval/cases](crates/vf-core/tests/eval/cases)のJSONです。

合成した評価専用のデータで、実文書での精度や性能を示すものではありません。推定座標が正解位置と一致するのは、合成フォントの文字幅が推定の前提（全角1em・半角0.5em）と同じためです。描画時はグリフを代替するため、見た目の再現は対象外です。
